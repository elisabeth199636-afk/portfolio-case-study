## 1. 项目定位与核心卖点

面向视觉、UI、品牌设计师，以中文指令把项目素材组织为可交接制作的案例策划；现有交付覆盖工作流、判断规则和输入输出模板。

临时主线：**让案例判断能够追溯到素材，并把判断转为展示方案。** 核心卖点是“事实边界—主线选择—章节证据—制作交接”的组织方式，依据 M01–M07。它能证明文档中存在这些设计安排，尚不能证明使用更高效；个人能力归属与求职岗位匹配待确认。

## 2. 项目类型判断及理由

选择 **D 未知／混合型，暂定**。主要变化落在信息组织、策划判断和输出约束。没有旧新任务流程与使用验证，不足以确认为 A 体验改版；没有品牌定位、形象资产，不支持 B；文档规则也不等于视觉资产规则，不支持 C。后续若补有真实工作流变化，可重新判断 A 是否适合作辅助线；当前不强行归类。

## 4. 逐章节核心标题与精简正文

### C01 将策划判断交接为展示方案

工具通过中文工作流连接材料整理、类型判断、叙事、版式与质检。已交付七份文档；当前成果是策划规范，没有可展示的产品界面或自动执行结果。

### C02 允许不完整输入，先明确已知与未知

输入模板允许自由描述和“未知”；主指令要求查看可访问素材、编号并区分事实、观察、推断与待补。它提出了处理材料缺口的方式，真实需求来源仍待补充。

### C03 先看问题和交付，再决定案例类型

类型规则要求依据核心变化选择主线，并为未知项目保留开放判断。叙事规则把问题、判断、证据与价值边界连接起来；这是现行规则的可见结构，不是已知的历史探索过程。

### C04 每章同时回答“讲什么”和“怎么证明”

输出模板保留八项结果，将章节正文、素材证据、阅读顺序和制作建议对应起来。版式参考按证明目的选择布局，质检再约束结论强度；是否降低交接返工尚待验证。

### C05 从自由描述走到章节交接

现有文件规定了输入、判断、输出的使用路径。作品集可据此制作路径示意；若补做演示，必须标为“回顾补充／概念演示”，不能写成真实客户应用。

### C06 文档交付已可查，使用效果仍待验证

当前能够核对工作流与模板之间的对应关系；不能声称策划质量提升、节省时间或获得用户认可。下一步应补齐职责与真实使用证据，再决定结果章节的结论强度。

## 7. 设计逻辑与真实性检查

| 检查 | 状态／边界与下一步 |

| 主线、类型与交付一致 | 通过：基于 M01–M07，保留 D 暂定 |
| 结论可追溯、八项交付及制作信息 | 通过：章节对应文件；新画面均标待制作 |
| 个人职责、需求来源、公开范围 | 待补充：未确认前不用“我主导”等措辞 |
| 实际使用与效果 | 待补充：不将规则存在当作规则有效 |
| 历史对比、品牌资产、动效状态 | 不适用：当前证据不支持这些展示；不补造 |

建议验证（尚未执行）：假设一，规则能约束无来源结论；指标为输出中无法定位依据的断言数及未知信息标注完整性。用经授权、含明确缺口的真实材料，固定任务与人工审核口径，留存输入、输出及复核记录；先建当前基线，再与事先确定的事实约束比较，关键事实不得越界。模型版本和审核判断会影响结果。

假设二，输出足以支持章节制作；由目标设计师用同一份材料完成交接，记录必须追问的信息、缺失的素材映射及返工原因。先确定岗位与交接验收标准，逐项核对是否可制作；无基线不宣称效率提升，少量案例不能代表普遍效果。
