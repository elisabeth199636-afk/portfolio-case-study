# “徽章视觉升级”案例初步策划

策划状态：初步。项目完成状态：未知；验证状态：待验证。仅收到本轮文字描述，未查看任何设计文件；未上传不等于未制作。以下结构均为策划建议。

## 1. 项目定位与核心卖点

一句定位：面向〔使用对象／情境待补〕，围绕〔真实升级问题待补〕，以方案取舍和资产规则组织徽章视觉升级案例，当前仅规划展示。

拟定核心卖点：说明“为什么选这个方向，以及如何将选择转化为可复用规则”。必须由真实比较、决策依据、规则与覆盖样例共同支持，暂不能写成已有能力成果。目标岗位、个人职责未知，不使用“主导”“独立完成”等表述。

## 2. 项目类型判断及理由

暂按 C 视觉体系型策划，判断把握：信息不足。依据是用户希望突出多方案比较与体系化设计，尚非已核实的项目问题和交付。若实际核心是品牌表达，应转向 B；若核心是任务理解与反馈，则重新考虑 A。暂不增设品牌策略、体验流程等辅助主线。

## 3. 推荐章节、导航与节奏

| 编号／导航 | 叙事功能与唯一问题 | 密度 |
| --- | --- | --- |
| C01／概览 | Hero＋Overview：做了什么、本人负责什么？ | 低，成果大图 |
| C02／问题 | Problem：为何需要升级？ | 中，可比证据 |
| C03／取舍 | Strategy：凭什么选择方向？ | 高，核心比较 |
| C04／体系 | Solution：规则如何覆盖资产差异？ | 高，规则到矩阵 |

首屏合并成果和概览，减少铺垫；比较提前，回应主要卖点。规则与全量放在同章，直接检验规则能否落到资产。若素材仍少，应用缩为待补说明，不以样机填满长页。建议 PC 纵向长页，左侧短导航对应六章，正文承担长标题；篇幅短时取消导航。

## 4. 逐章节标题与精简正文

**C01｜以方案判断与规则组织徽章升级（拟定主线）** 〔成果、范围、职责待填〕。首屏注明实际完成／概念提案等真实状态，未确认前保留未知。

**C02｜升级原因需要从旧资产与使用要求中确认** 〔具体问题待补〕。获得旧稿后，才能描述可见差异；不预写“风格混乱”“等级难辨”等痛点。

**C03｜让方向选择对应明确的比较条件（建议）** 若有历史方案，展示同一样本的真实取舍；若无，新增探索标“回顾补充”，不能作为原项目决策经过。

**C04｜用共同规则与变化规则解释资产关系（建议）** 待核实共同骨架及可变维度，再用全量清单核对覆盖。类别、等级或状态仅在项目确有需要时出现。

**C05｜在实际尺寸和载体中检查设计（建议）** 〔场景与约束待补〕。实际应用、原型和概念演示分别标注，不将展示样机写成上线证据。

**C06｜先说明交付边界，再提出验证问题** 目前未收到交付清单及结果数据，无法确认覆盖范围或效果。后续分别补交付记录与建议验证，不用效果形容词代替证据。

## 7. 设计逻辑与真实性检查

| 检查项 | 状态与下一步 |
| --- | --- |
| 八项结构、章节证据占位和状态边界 | 通过；仅指本次策划结构 |
| 类型、问题、职责及实际完成程度 | 待补充；核对 D01／02／03 |
| 比较可比性、选择依据与体系覆盖 | 待补充；核对 D04／05／06，不能宣称已验证 |
| 场景落地与业务效果 | 待补充；D07／08 缺失，不写上线或增长 |
| 独立体验流程、品牌推导、动效参数 | 当前不适用；无相关需求依据 |

**建议验证一：识别。** 假设为规则能支持真实所需的类别／等级／状态区分；指标为正确数／有效判断数、识别耗时和混淆项。由目标使用者在实际尺寸、背景下盲识别代表及边界资产，平衡呈现顺序并记录答案。与旧版或真实候选方向同条件比较；无基线先建立，判定标准须事前结合任务要求确认。对象、样本与任务待定，偏好不能替代识别，更不能推导业务增长。

**建议验证二：覆盖。** 假设为规则可解释全部已确认交付；按“有规则且样例符合的适用资产数／适用资产总数”记录覆盖与例外。由设计及协作方对照清单审查，用项目确认的交付范围和验收要求判定，先澄清例外再下结论。该审查仅证明规范覆盖，不能证明用户效率。
