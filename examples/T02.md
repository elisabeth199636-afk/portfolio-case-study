# IP 形象升级｜作品集初步策划

> 项目完成状态：未知；验证状态：未知。已提供事实仅为项目名称及希望突出“设计推导、视觉资产”；来源为本次用户描述。未上传品牌定位、旧形象、草稿、定稿或场景资料，暂无可见观察。下文是策划建议，不能作为已完成设计或项目成效的陈述。

## 1. 项目定位与核心卖点

一句话定位：围绕〔待补：品牌、受众与使用情境〕的〔待补：升级原因〕，呈现 IP 形象的关键设计判断及资产组织方式；实际交付范围待补。

候选核心卖点：让招聘方看懂“为什么这样画，以及这个判断如何延续到资产中”。需要真实推导稿、取舍记录与定稿规则共同支持；当前只是叙事目标，尚不能认定为个人能力成果。目标岗位、本人职责与团队边界待确认。

## 2. 项目类型判断及理由

当前判断为 **D 未知型，信息不足**。用户指定了展示重点，但未提供核心问题和实际交付，不能仅凭“IP 升级”判为品牌视觉项目。

若材料证明重点是品牌表达与角色识别，可采用 B 品牌视觉型主线；若主要解决成套资产的统一与差异，则转向 C 视觉体系型。以下暂借品牌推导与资产展示的结构策划，不预设完成品牌策略、完整系统或产品体验改版。

## 3. 推荐展示章节、导航与节奏

| 编号／导航 | 叙事功能与唯一问题 | 密度／承接 |
| --- | --- | --- |
| C01 成果概览 | Hero＋Overview：项目交付和本人范围是什么？ | 低；先建立项目尺度 |
| C02 升级依据 | Problem：什么真实差距需要改变？ | 中；给推导设约束 |
| C03 设计取舍 | Strategy＋Solution：依据如何变成造型选择？ | 高；全篇重点 |
| C04 资产规则 | Solution：核心判断如何延续到资产？ | 中高；由单体到组合 |
| C05 场景适配 | Application：资产如何进入使用情境？ | 低；从规则回到使用 |
| C06 交付边界 | Impact：目前能证明什么？ | 中；交代限制与下一步 |

合并首屏与概览，避免资料不足时拆出空页；推导与资产分别成章，给两种能力独立证据。内容形成后可用左侧短导航对应六章，内容较短则取消。大成果、对照、推导细节、资产全景、场景图交替，不平均分配篇幅。

## 4. 逐章核心标题与精简正文

**C01｜以关键成果呈现升级范围〔待定稿后改写〕** 选择最能代表交付的一张成果，配品牌、时间、角色和项目状态。定稿未提供，当前保留主图占位；不描述角色外观。

**C02｜先确认需要改变的表达差距** 依据品牌目标和旧形象，指出能被图或需求记录支持的问题。保留什么、改变什么均待核实，不预写“老旧、缺乏亲和力”等痛点。

**C03｜让造型选择回应明确依据〔建议主张〕** 从真实决策中选择最关键的一条，呈现依据、形态转译与取舍。只有确实比较过的方向才能进入历史方案；没有草稿时，改用明确标注的回顾分析。

**C04｜用可说明的规则组织视觉资产〔待证据〕** 将实际存在的轮廓、比例、色彩或组合规则落实到资产样例。表情、动作、视图等按实际交付选择，不默认齐全，也不把单张海报写成完整系统。

**C05｜用具体载体检验适配方式〔建议〕** 选择与真实用途有关的场景，说明尺寸、背景或内容约束如何影响使用。无应用材料时保留空缺，后补样机标明“概念演示”。

**C06｜把交付事实与待验证目标分别写清** 核对最终交付、实际使用和验证记录。没有结果材料时，仅列范围与未解决事项；不写品牌认知提升、用户喜爱或商业增长。
