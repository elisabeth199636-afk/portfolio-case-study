# portfolio-case-study

为互联网视觉设计师、UI 设计师和品牌设计师策划求职作品集案例的中文 Codex Skill。

输入项目背景、设计截图、过程稿和设计说明，组织出一条能由真实设计证据支持的案例主线，并给出章节文案、PC 长页展示方案和制作优先级。

**版本：v1.2 · 策划、审美方向、视觉参考校准与可选 HTML 组件 · MIT 许可证**

在 v1.1 基础上加入正向／反向视觉参考处理与可覆盖的展示审美方向。公开包只含通用规则、模板和占位组件，不包含用户项目或参考原图。

## 适合什么项目

| 项目类型 | 展示重点 |
| --- | --- |
| 体验改版 | 业务与任务问题、方案探索、关键流程、状态、动效和验证 |
| 品牌视觉 | 品牌定位依据、形象推导、设计取舍、资产系统、规范与场景 |
| 视觉体系 | 旧体系问题、多方案比较、决策、统一与差异规则、全量资产和应用 |
| 未知或混合 | 从项目自身的问题、决策、交付与情境组织叙事，不强套前三类 |

它侧重项目价值与设计判断的表达。每个关键结论需要真实素材或明确的待补项；不编造研究、业务数据、历史方案、上线结果或个人贡献。

## 安装

需要能读取本地 Skills 的 Codex。查看截图和附件还需当前运行环境支持相应文件。默认工作流以指令和参考文件为主，不需要命令行脚本或后端服务；可选首页组件是浏览器运行的自包含 HTML。

### 下载 ZIP

1. 打开 [v1.2 Release](https://github.com/elisabeth199636-afk/portfolio-case-study/releases/tag/v1.2)，下载 `portfolio-case-study-v1.2.zip`。
2. 解压得到 `portfolio-case-study/`。
3. 将整个文件夹放入 `~/.agents/skills/`，使主文件位于 `~/.agents/skills/portfolio-case-study/SKILL.md`。保留 `references/`、`assets/` 和 `agents/`。

### 使用 Git（macOS / Linux，尚未安装时）

```bash
mkdir -p ~/.agents/skills
git clone --branch v1.2 --depth 1 https://github.com/elisabeth199636-afk/portfolio-case-study.git ~/.agents/skills/portfolio-case-study
```

以上命令安装固定的 v1.2 标签版本。Codex 会自动检测 Skill 变化；若列表没有出现，再重启 Codex。安装位置与调用方式见 [OpenAI 官方文档](https://learn.chatgpt.com/docs/build-skills)。

## 调用

安装后，在 Codex 中输入并附上真实素材：

```text
$portfolio-case-study
请根据我附上的项目背景、设计截图与过程稿，策划求职作品集案例。
目标岗位：【填写或写暂未确定】
我的实际职责：【填写或写未知】
已完成内容及项目状态：【填写】
已有研究、数据或结果依据：【有则附来源，无则写无】
请输出完整八项策划，以 PC 长页为主，评估是否适合左侧章节导航。
```

替换示例中的提示栏。不知道的信息保持未知，不必为调用填满所有字段。也可复制 [项目输入模板](assets/project-input-template.md)，或直接自由描述和上传文件。

如果材料不足，会先给初步策划、待补清单和制作顺序；仅对会改变主线、归属或披露范围的信息提出必要问题。项目名并不等于已确认类型。

## 会得到什么

1. 项目定位与核心卖点。
2. 项目类型判断及理由。
3. 推荐作品集展示章节。
4. 逐章节核心标题与精简正文。
5. 每章展示重点、视觉证据和版式建议。
6. 素材使用及待补充清单。
7. 设计逻辑与真实性检查。
8. 具体制作优先级、依赖和完成标准。

Hero、Overview、Problem、Strategy、Solution、Application、Impact 是可调整的叙事功能，不限定七页。展示建议包括图文层级、阅读顺序、对比、流程、关键状态、规则和场景，适合后续在 Figma 中手工制作。见 [完整输出模板](assets/output-template.md)。

## 首页自定义（v1.1，按需启用）

用户要求制作实际本地 HTML 版式时，可以加入：从本机选图／拖入图片、关联设计文件链接、本机保存、恢复默认、下载修改后的离线 HTML。纯策划任务保持原有八项输出。

```text
$portfolio-case-study
请根据我的项目素材制作本地 HTML 作品集版式，
首页支持上传封面、关联设计文件链接、恢复默认和下载修改版。
所有项目素材和结果仅留本地。
```

实现规则见 [首页自定义说明](references/home-cover-editor.md)。[通用组件示例](assets/home-cover-editor.html) 不包含任何客户项目或设计图片；下载后可用本地浏览器打开，GitHub 文件页面只展示源码。它是功能起点，完整作品集的叙事和视觉需要依据用户素材制作。

图片不上传服务器；链接作为“查看设计文件”的入口，不会自动转为截图，也不改变原平台权限。图片与设置按案例保存在浏览器中；可下载 HTML 留存。PNG／PDF 是静态输出，不具备真正的上传功能，也不会随 HTML 编辑自动更新。

开源此 Skill 不等于授权公开之后输入的项目素材、设计稿或个案输出。只有用户另行明确要求才发布相应内容。

## 正向／反向视觉参考（v1.2）

调用时可附上喜欢与不喜欢的设计案例，并说明参考用于作品集外层、原项目界面还是局部细节。Skill 会区分观察与偏好推断，比较正反案例的共同特征，把采用／避开的规则映射到具体章节，不把深色、渐变、卡片等特征一刀切。

```text
$portfolio-case-study
请结合项目素材与正向／反向参考策划作品集。
保留项目已确定的品牌方向，说明各章节采用和避开的处理及其依据。
```

可直接采用 [展示审美方向](references/visual-style-guide.md)：大图与观点标题、主辅明确的成果组、有实际内容的卡片、统一材质和章节疏密；避开通用企业官网式模块堆砌与无主次拼贴。支持深色和浅色，不把任何一种配色或固定布局当成所有项目的答案。

参考处理规则见 [视觉参考校准](references/visual-references.md)。个人偏好可选存为安装目录的 `references/local-visual-preferences.md`；此文件及个人原图不属于公开发行包。其他使用者使用自己的参考。

## 测试与示例

先读 [测试材料与方法](references/testing.md)，再用 [质量检查表](references/quality-check.md) 检查结果。已有输出：

- [T01 用户任务升级](examples/T01.md)：缺资料时的流程、状态与动效策划。
- [T02 IP 形象升级](examples/T02.md)：缺资料时的设计推导与资产策划。

前三例没有真实视觉原稿，只用于检查资料不足时的处理；第四例仅检验文本级泛化。它们不是可直接套用的真实项目案例。公开副本仅将本机绝对路径替换为通用安装路径，未改写策划正文。详见 [验证记录与未完成事项](docs/validation.md)。

v1.1 首页组件的实际检查见 [组件验证记录](docs/home-cover-validation.md)。原四个示例仍是 v1.0 的历史文本测试，不代表重新完成了真实视觉项目验收。

## V1.2 的限制与后续方向

- 默认输出案例策划；按需制作本地 HTML 版式与首页控件，不自动排版 Figma、部署在线网站或产出研究结果。
- 读图能力取决于运行环境、素材质量和可访问性；无法查看的素材应明确标记。
- 能核对已提供的证据与表达边界，不能自动证明用户陈述和原始数据真实。
- 尚缺前三类真实视觉项目验收；未知类型仅有本次工具文本样本，泛化范围有限。
- 已完成显式读取 Skill 的文本行为检查；隐式选择命中率和跨客户端表现尚未验证。

后续优先收集允许公开或已充分匿名化的真实项目，校准类型判断、证据链、章节节奏和制作交接；依据实际失败调整规则。

v1.2 实际检查范围与未测试分支见 [更新验证](docs/visual-reference-validation.md)。
