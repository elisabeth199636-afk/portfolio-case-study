# 项目类型与展示重点

## 先判断核心问题

分类用于选择证据和叙事，不是贴标签。先看“为什么做、主要改变什么、实际交付是什么”，再参考项目名。

| 类型 | 核心变化 | 首选证据 |
| --- | --- | --- |
| A 体验改版型 | 人完成任务的方式、路径、理解或反馈 | 旧新流程、关键页面、交互状态、动效说明、验证 |
| B 品牌视觉型 | 品牌定位的表达、形象识别与延展 | 定位依据、形象推导、取舍、资产与规范、应用 |
| C 视觉体系型 | 一组资产之间的规则、一致性与差异 | 体系审计、多方案比较、决策标准、规则、全量资产和状态 |
| D 未知／混合型 | 以上不足以解释，或多类目标共同成立 | 从实际问题、决策、交付、使用情境中选择证据 |

写出依据与判断把握（明确／暂定／信息不足即可，不生成伪精确概率）。仅有“用户任务升级”不能确定是流程优化还是任务徽章视觉升级；可暂定并说明歧义。仅有“IP”也不能证明包含品牌策略。

## A. 体验改版型

**主线**：任务或业务问题 → 旧体验阻碍 → 目标与约束 → 探索和取舍 → 新流程与状态 → 应用与验证。

- 对比同任务、同入口、可比版本的旧新流程，突出变化节点；不用不同场景的两张图作因果对比。
- 展示关键步骤及必要分支，不只展示首页。按项目需要选初始、进行、完成、失败、返回等状态；不存在的状态待确认，不宣称已设计。
- 动效说明含触发、变化、结束反馈、作用及静态替代，用关键帧或标注录屏表达。时长、缓动和手势参数只用已提供值，其余标为建议。
- 真实探索说明比较的是信息组织、路径还是反馈，用实际约束解释取舍。

Solution 可围绕路径、信息与反馈、关键状态展开，数量由材料决定。装饰动效不强行写成效率提升机制。

误区：把变美当作任务已解决；有原型就宣称上线；步骤变少就宣称完成率增长。

## B. 品牌视觉型

**主线**：品牌与受众背景 → 旧表达与目标的差距 → 概念与推导 → 形象决策 → 资产系统与规范 → 场景延展。

- 使用真实定位和旧形象，区分原有定位与设计师提出的新方向；没有研究不创造受众洞察。
- 推导说明概念如何转为轮廓、比例、色彩、表情或动作。只有结果不倒编历史演变线。
- 展示实际比较过的方向和淘汰理由；只有定稿时诚实说明。
- 展示实际主视图、表情／动作／组合资产及可复用规则；单张 IP 海报不包装成完整品牌系统。
- 场景解释尺寸、载体与内容适配，明确实际应用、样机演示或概念延展。

IP 若主要改变产品引导或反馈，也可能 A 为主、B 为辅，需由目标与交付证明。

误区：编抽象价值观硬套造型；用样机数量代替推导；把审美喜好写成用户认可。

## C. 视觉体系型

**主线**：旧体系问题 → 升级目标 → 多方向比较 → 方案选择 → 统一与差异规则 → 全量资产、状态和应用。

- 旧资产全景与局部对比指出构图、尺度、材质、色彩、等级或状态区分问题；无旧图时只能列为待核问题。
- 多方案在相同资产、尺寸与背景下比较，说明辨识、系列统一、小尺寸适配或生产约束等评价维度与取舍。无权重依据时定性说明，不虚构评分。
- 区分共同规则与按等级／类别变化的规则，落实到可见样例。
- 全量矩阵标清类别、等级、状态；只有部分定稿就展示已知覆盖并列缺口，不补虚假数量。
- 选择实际需要的未获得／已获得等状态及应用尺寸，不默认所有徽章项目同一套状态。

章节可围绕“为何选该方向”“如何统一并区分”“怎样覆盖场景”，不按单个资产各建一章。

误区：只有成品无规则；比较只说“更高级”；用设计系统标签包装一次性合集。

## D. 未知或混合类型

不以“最像 A/B/C 哪个”为唯一判断，先重建：

1. 要改变的具体问题及受影响对象。
2. 实际关键决策与约束。
3. 已有交付及使用情境。
4. 支持判断的过程、结果与缺口。

据此命名工作类型，或保持类型未定。若目标主要关乎信息理解、内容组织或空间使用，可用项目自己的问题定义主线；这只是分类思路，不代表用户项目具有这些事实。

混合项目选证据充分、最能体现岗位能力的主线，其他内容支持主线时再加入。两条独立主线确有必要时采用双线结构，说明共用背景与独立决策证据，不简单拼接三类章节。

未知项目可保留七种叙事功能，Solution 必须来自项目本身，不默认需要角色表情、任务流程或徽章等级。信息不足时给开放待补项和条件性结构，不发明新类型名称。
