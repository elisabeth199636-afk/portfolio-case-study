# V1.0 测试材料、方法与输入示例

## 先区分测试能证明什么

先准备材料清单与方法，再执行。没有真实项目原稿时，不制造“原始项目事实”、测试数据或过程截图。下列前三个输入只复用需求给出的项目名称和关注点，不包含真实项目内容，只能用于缺资料测试。第四个使用本次实际创建的 Skill 文本文件作为异类输入，只能检查文本级泛化，不能替代视觉项目验收。

## 四类测试材料清单

所有用例共需：项目背景来源、核心问题与约束、个人职责、项目完成状态、可公开范围、带名称和版本的素材清单、结果证据（没有就明确无）。缺失不阻止初步策划，但会限制结论。

| 用例 | 真实项目验收所需材料 | 核心检查 |
| --- | --- | --- |
| T01 用户任务升级 | 同任务旧新版入口与关键步骤；关键分支／状态；实际探索及取舍；已有动效录屏或连续状态稿，未制作则注明；若有验证则提供方法和来源 | 重点是否落在任务路径和反馈；是否策划关键状态、动效触发／变化／结束／静态替代；不将视觉改善写成行为增长 |
| T02 IP 形象升级 | 品牌定位来源与旧形象；真实概念／草稿／比较方向；定稿；实际表情、动作、组合等资产；规范与应用，区分样机；如有反馈需原始依据 | 是否能追溯概念到形态；是否解释实际取舍；资产系统与场景有无证据，不倒编品牌洞察 |
| T03 徽章视觉升级 | 旧资产全景；实际比较方向及同样本图；决策记录；统一与差异规则；现有全量或子集；实际等级／状态／尺寸／场景；如有验证需口径 | 是否比较同条件方案并解释决策；是否区分共用与变化规则；是否展示覆盖缺口，而非只排定稿图 |
| T04 新的未知类型 | 一个真实、不以前三类为核心的项目，提供其问题、决策、交付与使用情境；不要预设必须有任务、IP或徽章。当前可用本次 Skill 的真实文本文件 | 是否根据实际目标组织主线、保留未知信息；是否避免硬套前三类的资产与指标；文本案例不宣称通过视觉阅读检验 |

## 可直接使用的测试输入

### T01：用户任务升级，无真实资料

```text
$portfolio-case-study
我要策划“用户任务升级”案例，希望重点呈现体验流程和动效。
目前只提供这个题目，没有上传项目背景、设计截图、过程稿或结果资料。
请先给出初步策划、素材清单和可执行的下一步；如关键信息影响主线再集中问我。
```

### T02：IP 形象升级，无真实资料

```text
$portfolio-case-study
我要策划“IP 形象升级”案例，希望重点呈现设计推导和视觉资产。
目前没有上传品牌定位、旧形象、草稿、定稿或场景资料。
请基于这些有限信息给出初步策划，缺失内容保持待补充。
```

### T03：徽章视觉升级，无真实资料

```text
$portfolio-case-study
我要策划“徽章视觉升级”案例，希望重点呈现多方案比较与体系化设计。
目前没有上传旧稿、对比方案、规则、全量资产或使用场景，没有结果数据。
请给出初步策划及制作优先级。
```

### T04：新的未知类型，使用本次真实文件

执行前将下面的文件位置替换成当前可读取的 Skill 文件或直接附文件，避免迁移后的绝对路径失效。

```text
$portfolio-case-study
我想策划一个未归类案例：本次 portfolio-case-study 作品集案例策划工具的设计。
已存在的交付是 SKILL.md、四份叙事/类型/版式/质检参考文件、输入和输出模板。
它通过中文指令组织策划工作流，面向视觉、UI、品牌设计师；本轮没有 Figma 自动排版或网站实现。
请实际读取我附上的上述文件，以可见内容作为设计证据。
我的个人设计职责未说明；没有用户研究、使用数据、验证结果或视觉界面截图。
请判断适合的案例主线，不预设项目属于体验、品牌或视觉体系，并给出完整策划。
```

T04 中“已存在”只指能实际读取的文件；不因此声称工具已经稳定运行、用户已认可或交付在某个范围产生了效果。本次可用文件只是异类输入，不代表已取得真实视觉项目。

## 测试方法

1. **结构检查**：运行 skill-creator 的 `quick_validate.py`；另查 YAML 的 name、description、metadata.version、文件夹同名、所有相对链接可解析、无初始化占位、无不必要脚本。模板的待填栏是有意保留，不是未完成脚手架。
2. **缺资料执行**：分别提交 T01–T03，每次独立上下文，只提供输入和 Skill，保存完整输出。检查是否仍给出八项初步结果、是否诚实说明未看图、分类是否暂定、关键资料是否待补。不要以指定词句是否出现作为唯一标准。
3. **异类执行**：提交 T04 及实际文件，检查输出引用是否真实、章节是否回应工具设计的实际问题、是否避免虚构视觉过程。材料或交付变化时更新 T04，不把未来计划当现状。
4. **真实项目验收（资料齐备后）**：用各类型真实原稿重跑；逐条检查“结论—设计判断—素材位置”的支持关系，人工核对画面是否可读、对比是否可比、方案决策是否确有依据、版式是否可制作。未知项目另换一个未参与规则编写的真实项目，避免只对本次工具有效。
5. **边界检查**：从真实输入移除关键证据，或仅追加“请写成研究验证过／提升很大”等无依据请求。检查是否保持事实边界、把可写的设计动作与不能写的效果分开。不要为测试编一个假增长数字。
6. **回归与记录**：用 [质量检查表](quality-check.md) 记录实际观察、证据位置、通过／需修正／待补充／不适用。发现失败只做有依据的针对性修正，重跑受影响用例。记录未执行的检查，不用结构通过冒充行为通过。

## 验收判据

- 真实性为必要条件：任何虚构事实、伪装读图、假结果或假个人贡献均为需修正，不能靠其他优点抵消。
- 标准八项输出齐全，各章可追溯到素材或明确待补项；没有材料时仍有有用的准备顺序和依赖，不仅输出问卷。
- 类型差异体现在证据与展示逻辑，而不只更换标题。无动效、无多方案或无全量资产必须写明缺口。
- 未知类型能从自身问题组织章节，不要求用户先塞进三类；没有指标依据时先定义验证问题。
- 真实项目验收还须核对截图、过程、应用证据和 Figma 制作可行性。无真实素材时，该项状态为待验证。
