# 输出质量与真实性检查表

## 结论强度

| 现有证据 | 可以表达 | 不可以据此声称 |
| --- | --- | --- |
| 定稿 | 可见结构、设计动作、已提供交付范围 | 用户偏好、研究结论、效率或业务提升 |
| 旧新截图／流程 | 可比范围的变化；必要时注明人工计数方法 | 改动已造成效果或用户认可 |
| 原型、动效稿 | 演示的交互与反馈机制 | 已上线、实际行为已改变 |
| 样机／概念场景 | 计划适配或演示效果 | 已投放、实际使用或品牌增长 |
| 用户口述结果 | “据项目说明／用户陈述”，待核实 | 已独立验证或严格因果归因 |
| 有来源的数据／测试 | 对象、时段、方法和口径支持的有限结论 | 超出样本、把相关写成因果、忽略其他改动 |

## 交付前逐项检查

用“通过／需修正／待补充／不适用”记录，未通过项写位置、原因和下一步。未知不能记为通过，不固定打总分。

### 定位和叙事

- [ ] 核心卖点是否指向具体设计判断和证据，而非“提升体验”等口号？
- [ ] 类型判断是否来自目标与交付？暂定或混合类型是否交代歧义与主线？
- [ ] 章节是否围绕问题和决策，而非按文件夹或时间流水账？
- [ ] 七种叙事功能所需信息是否保留？合并、拆分、缺失是否有解释，而非固定页数？
- [ ] 每章是否一个核心问题，标题有观点且不超过证据强度？
- [ ] 正文是否精简，可由图承担的细节是否已转为标注？

### 证据和真实性

- [ ] 关键结论是否有来源、素材编号或待补项？是否假装看过不可访问图片？
- [ ] 事实、观察、推断、待补是否区分？口述和原始证据是否分清？
- [ ] 实际完成、概念提案、后续规划、验证状态是否分别可见？
- [ ] 个人贡献和团队产出是否分开，未知职责是否仍未知？
- [ ] 是否虚构数据、访谈、研究、A/B 测试、上线、历史方案或反馈？如有须删除或改成明确建议，不能只加总免责声明。
- [ ] 对比是否版本和情境可比？后补探索是否标为回顾补充？
- [ ] 结果的对象、时段、样本、方法与口径是否支持结论？设计独立影响是否确可归因？

### 展示和制作

- [ ] 每章是否有重点、证据、版式、阅读顺序与素材？
- [ ] 体验流程是否有关键节点和必要状态？动效是否有触发、变化、反馈与静态替代？不适用说明原因。
- [ ] 品牌项目是否有据可查的推导、真实资产和场景标签？
- [ ] 体系项目是否有比较、标准、统一与差异规则、覆盖与适用状态？缺项是否可见？
- [ ] 长页是否主次明确、密度有变化？导航是否必要且对应正文？
- [ ] 素材是否可读、可定位？复用是否有不同证明目的？
- [ ] 待补清单与优先级是否具体，有依赖和完成标准？
- [ ] 八项输出是否齐全，避免重复正文或无证据填空？

## 无数据时的验证规划

每条方案写成：**待验证假设 → 指标定义 → 对象／任务或场景 → 方法与采集 → 基线／比较 → 判定原则 → 限制**。不生成结果、伪造样本量或自行指定提升比例。

以下是方法示例，不能当作项目现状：

| 方向 | 指标 | 可执行方法 | 边界 |
| --- | --- | --- | --- |
| 任务理解／完成 | 成功率（先定义成功）、时间、误操作、状态理解 | 真实目标用户用同一任务脚本操作原型／产品，记录设备、顺序、帮助情况 | 样本招募待定，学习和其他改动可能干扰 |
| 形象识别 | 识别准确、品牌联想一致性、跨场景辨认 | 同曝光条件下识别和开放联想任务，事先定义编码依据 | 偏好不等于识别或商业效果 |
| 资产体系 | 类别／等级／状态区分正确、识别耗时、小尺寸可读、规则覆盖 | 代表性及边界资产做盲识别与规范审查，记录混淆、缺口 | 规范审查不能单独证明用户效率 |
| 未知类型 | 按问题定义可观察行为或交付标准 | 先确认对象、情境与设计意图，再设计方法 | 不照搬前三类指标；必要时仅评审是否满足约束 |

与旧版、当前基线或事先确定的验收标准比较。无基线先建立基线；阈值依据任务风险、已有标准和实际条件确定，不任意编造。研究招募和执行属于后续工作，本 Skill 只提供可审核的规划。

## 修正顺序

先修事实和归属，再补主线证据，其次调整结构与版式，最后精修文案。缺数据不阻止展示真实设计，但限制结果声明。

## 按需检查：首页自定义

只在交付实际 HTML 及首页控件时启用；纯策划标为不适用。

- [ ] 上传图片能预览、应用和恢复；读图失败、大小超限与非法格式有反馈。
- [ ] 先填链接后选图、先选图后填链接均保留输入，不因图片异步回调覆盖草稿。
- [ ] 链接限制为 http／https，作为源文件入口，不假装解析出封面或改变原平台权限。
- [ ] 刷新后按案例恢复本机设置；不同案例互不覆盖；持久化失败时说明实际状态。
- [ ] 修改后导出、离线重开、再次修改并再导出均可运行，按钮不保留忙碌或禁用状态。
- [ ] 桌面、手机和键盘操作可用，下载说明与实际文件一致。
- [ ] 原始素材与个案结果没有因使用开源 Skill 自动进入公开仓库或远端服务。
