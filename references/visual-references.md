# 正向与反向视觉参考

## 何时读取

用户提供喜欢／不喜欢的案例、参考目录、已有风格偏好，或要求据此调整作品集时读取。没有参考时依据项目素材策划，不额外索要情绪板。

若当前安装目录存在 `references/local-visual-preferences.md`，可作为本机用户的偏好背景读取；当前项目的明确要求优先。该可选文件不属于公开发行包，不依赖它才能使用 Skill。不要替其他用户寻找原作者的参考目录。

## 从图片到可执行的判断

1. 先查看实际图片并编号，分别记录正向 P、反向 N。区分原项目界面、作品集外层展示、品牌氛围和局部细节的用途；看过缩略图不等于读清长页正文。
2. 沿构图、主次、图文比例、字体层级、素材分组、颜色与材质、章节节奏分别描述可见特征。把“可见观察”和“推测用户喜欢／不喜欢的原因”分开；目录标签只确定整图的正反归属，不证明用户对每个细节的态度。
3. 找正向中的共性，也找正反之间重叠的特征。例如双方都有卡片时，继续比较卡片承载的内容、尺度与层级，不能得出“禁止卡片”；喜欢深色参考也不自动推翻当前项目已选定的浅色方向。
4. 只提炼影响本项目的少量规则：**参考编号 → 可见特征 → 拟采用／拟避免的处理 → 适用章节 → 检查方式**。具体数量、比例和像素是本次制作选择，不升级成所有作品集的固定参数。
5. 将规则落实到已有八项输出的第 5 项版式、第 7 项检查和第 8 项优先级，避免再增加一套重复报告。纯策划写可制作的建议，实际 HTML 则检查渲染结果。

关键分歧确实改变结果才提问。其余说明采用了什么解释并继续；不让用户逐张评分或填写完整视觉问卷。

## 用于作品集，而不是替代作品

- 借鉴构图、尺度、节奏和说明方式；展示主体仍是用户的真实原稿。第三方参考不能冒充个人成果、历史探索或上线证据。
- 参考中的文案、数值、Logo、名人、评价和装饰不自动进入用户案例。没有这些资产时不照搬整个画面，也不补造项目事实。
- 强视觉可来自大图、清楚的标题、真实资产和有主次的组合；不通过堆空白容器、随机倾斜和无关 3D 来制造设计感。
- 卡片可承载成果、对比、状态或同类资产；是否采用取决于证明目的，不按风格名一律接受或排除。
- 深浅、渐变、圆角、字体及色彩均服从用户当前要求、品牌与可读性。参考中的局部风格不自动改写项目选定方向。

## 校准与交付

策划时列出关键章节如何响应正向规则、如何避开具体反向问题，并保留推断的边界。实际制作后检查：首屏能否辨认主角；图像是否足够清楚且能查看完整稿；说明是否贴近证据；章节是否因内容产生合理的疏密变化；缩到手机后顺序和重点是否仍成立。用实际位置或截图说明，不凭“高级、现代”自评通过。

个人参考与偏好文件默认本地保存。用户要求将审美参考更新到公开 Skill 时，可以提炼为 [可覆盖的展示方向](visual-style-guide.md)，明确适用范围；只发布文字规则、空白字段或有授权的演示素材，不复制个人图片、绝对路径、本机偏好文件或生成的项目页面。使用者仍可提供自己的参考。
